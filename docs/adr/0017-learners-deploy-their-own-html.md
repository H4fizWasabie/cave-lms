# Learners deploy their own HTML

Amends ADR 0003 and ADR 0007. A Deployment is now a page the Learner made themselves, typically by giving their Excel file and a prompt to ChatGPT, Claude or Gemini, uploaded as one `.html` file (at most 5 MB, counted in the Storage allowance) on a Dashboard's Deploy tab. Cave only hosts it at `cavelms.com/<prefix>/<name>`. The client asked for this: Learners want a dashboard of their own design, and what Cave sells is real hosting. The Lab and its engine stay as they are for learning: every logged-in Learner builds from Samples, looks under the hood and downloads the zip; a Plan adds own uploads and the Deploy tab, which is hidden without one. One Deployment per Dashboard; a new upload replaces the page at the same link, and the 3 earlier pages are kept to restore. Existing Deployments are converted once to HTML, the engine's page with its data inlined, at the same link.

This reverses ADR 0003's first rejection, strangers' scripts on our domain, so the page stays sandboxed as ADR 0007 requires, with a new policy: scripts, styles and fonts from a fixed list of CDNs (jsdelivr, cdnjs, unpkg, Google Fonts), images over https, and no way to send data out (`connect-src 'none'`, `form-action 'none'`), so a fake login form posts nowhere. A page can still navigate itself away; Takedown remains the answer, and ADR 0007's phishing cost grows with arbitrary HTML. Data is baked into the page, so updating it means making and uploading a new page: the fragility ADR 0003 named, now the Learner's to own. Rejected: (1) Cave generating the deployed page, the old way, which the client declined; (2) any https source, which lets a page load anything; (3) a Deployment with no Dashboard, which would need its own screens outside the Lab; (4) a Trial Deployment for free Learners, dropped because they have nothing to put online.
