# Learners deploy their own HTML

Amends ADR 0003 and ADR 0007; amended by ADR 0018, which removes the engine. A Deployment is now a page the Learner made themselves, typically by giving their Excel file and a prompt to ChatGPT, Claude or Gemini, uploaded as one `.html` file (at most 5 MB, counted in the Storage allowance) on a Dashboard's Deploy tab. Cave only hosts it at `cavelms.com/<prefix>/<name>`. The client asked for this: Learners want a dashboard of their own design, and what Cave sells is real hosting. The Lab and its engine stay as they are for learning: every logged-in Learner builds from Samples, looks under the hood and downloads the zip; a Plan adds own uploads and the Deploy tab, which is hidden without one. One Deployment per Dashboard; a new upload replaces the page at the same link, and the 3 earlier pages are kept to restore. Existing Deployments are converted once to HTML, the engine's page with its data inlined, at the same link.

This reverses ADR 0003's first rejection, strangers' scripts on our domain, so the page stays sandboxed as ADR 0007 requires, with a new policy: scripts, styles and fonts from a fixed list of CDNs (jsdelivr, cdnjs, unpkg, Google Fonts), images over https, and no fetching beyond Cave: `connect-src` allows only Cave's origin, so the page can read its own data and nothing else, and `form-action 'none'`, so a fake login form posts nowhere. It cannot fetch or post anywhere but its own data, but it is not sealed: an image from any https address, or the page navigating itself away, can still carry what a visitor typed to another site. Closing images would break the pictures chatbot pages load, and navigation cannot be closed at all, so Takedown remains the answer to a page that phishes, and ADR 0007's phishing cost grows with arbitrary HTML. The page stays live: Cave serves the Dashboard's current Dataset at `<link>/data.json`, and a page that reads it shows new data once the Learner confirms a new Dataset in the Lab, by replacing it or adding rows to it. The deploy screen gives a prompt to paste into the chatbot so the page reads that address instead of baking the data in; a page that bakes it in still deploys, and updating it means uploading a new page. A new Dataset whose columns differ from the current one is confirmed with a warning, since the page reads columns by name. Rejected: (1) Cave generating the deployed page, the old way, which the client declined; (2) any https source, which lets a page load anything; (3) a Deployment with no Dashboard, which would need its own screens outside the Lab; (4) a Trial Deployment for free Learners, dropped because they have nothing to put online.
