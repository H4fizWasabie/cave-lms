# Dashboards are built from the data; a Template is optional

Superseded by ADR 0018: Cave no longer builds Dashboards; the Lab deploys pages Learners made.

Amends ADR 0003. A new Dashboard starts from the Learner's upload: Cave cleans it and builds the blocks from the Dataset itself, by fixed rules over each column's values and name, with no AI and no Learner code. A Template is an optional starting point, offered when its columns are found, and a Dataset that lacks a Template's column is never refused: the blocks that need it are left out. Better rules apply to new Dashboards and to Reset only; a Dashboard's blocks are the Learner's (ADR 0013) and never change under a Deployment. Learners' real files rarely match a Template, and refusing one with no Amount column, as Templates did, stopped Learners whose data has no money in it at all. Practice Dashboards, which read uploads as they were, are closed (ADR 0015).

The rules are Cave's own Go code, and Deployments stay static files on R2 (ADR 0008). No open-source library cleans messy Excel (title rows, merged cells, totals, days-across grids) or picks charts for an unknown table without a server or Python; the ones checked (SheetJS, TabularJS, DuckDB, Frictionless, Metabase X-rays, Lux, Draco, Graphic Walker, Perspective) each cover one slice or need a running service. Rejected: a Streamlit or Python app per Dashboard (ADR 0003); parsing in the Learner's browser with SheetJS, which would mean rewriting Clean-up in JavaScript. If uploads outgrow the VPS, the same Go code can run in the browser as WebAssembly.

A column counts as numbers or dates when at least 90% of its filled cells are; the rest are left empty and listed as a Clean-up change before the Learner confirms. Only .xlsx is read; a .xls upload is told to save as .xlsx. One table per sheet: a second table on the same sheet is not looked for.
