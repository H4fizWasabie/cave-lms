# A Dataset grows in Parts, with no earlier copies

Amends ADR 0017 and ADR 0021. Learners upload the same kind of Excel report every day, week or month for years, whatever it holds, so a Dataset can reach hundreds of thousands of rows. A Dataset was one table capped at 50,000 rows, and each "add" rewrote the whole table and kept 3 earlier copies, so it hit the cap within months, held up to four copies in storage, and loaded everything into memory for every change. A Dataset is now made of Parts, one per confirmed upload. Adding data stores only the new Part, a Part can be replaced or deleted on its own, and a replaced Part keeps its place, so a page that takes the last row for a key still treats the newest upload as newest. `data.json` still returns every row, Part after Part, so pages written for ADR 0017 keep working.

A growing Dataset only works if every upload is read the same way, so the first Part sets the recipe (its sheet, matched by name ignoring case, and its header row only if the Learner typed it; otherwise Cave finds each Part's header row again, as the title rows above it may differ), and each new Part is read with it: Cave never combines other sheets into an added Part, and asks the Learner to pick a sheet when none has that name. The Dataset's columns are its first Part's: a new Part's extra columns are dropped and listed in the preview, and a Part missing one is refused. Before that, a column the Part is missing is read from one of its extra columns when the names are equal ignoring case, spaces, underscores and dashes (a note in the preview), else when the Learner picks it from a dropdown of the file's unused columns, which is offered on the refusal, on Add to data and on Replace of one Part. The Learner's picks (file column to Dataset column) are kept in the recipe, so the next file with the same headers maps itself, with a note, and can be changed in its preview; Replace data clears them with the recipe. The Dataset's column types and names win, as for any Part. The one exception is a month column, a number column whose values are all whole numbers from 1 to 12, found from the first Part's values and kept in the recipe: a month name in a new Part there (Ogos, Aug) is read as its number and listed in the preview, and a confirmed Part with another number in that column ends it, so the Dataset's values decide. A Dataset recorded before month columns existed is read once, Part by Part, on its next Add or Replace of one Part, to find them; after that, never again. Only the exact file of an existing Part is refused, with an offer to replace that Part; any other overlap is a note, since a report exported again each period often repeats most of the last one's rows. Every Part has a date, taken from the title rows above its column names, else its sheet name, else its file name, else the day it was uploaded, shown in the preview with where it came from and changeable there; `data.json` gives it on every row as a `Part date` column, so a page can tell snapshots apart and draw trends; an upload with a column of that name, ignoring case and spaces, is refused, as it would be overwritten. The recipe lasts while one Part remains.

Limits: each upload keeps the 50,000-row and 10 MB limits, which bound Clean-up's memory. A Dataset behind the Learner's own page has no row cap; only the Storage allowance limits it, and a bigger allowance is a Plan with more storage. A Dataset Cave builds a Dashboard from (ADR 0019) keeps a 50,000-row total, because the builder reads it whole. A Part counts against the allowance alongside its Workbook, as ADR 0021 decided, so the room a Dataset takes is about its Workbooks' size plus its rows as JSON.

Cave keeps no earlier Datasets and has no Restore. Each Workbook stays in the Folder, so a Part removed by mistake, or by replacing the data, comes back by adding it again from its Workbook. Picking a Workbook on a Dashboard (issue #401) becomes adding or replacing a Part from it. Existing Datasets become one Part each, keeping their Workbook link; their earlier copies stay until that Dashboard's data next changes.

Rejected: (1) raising the 50,000-row cap, which keeps whole-table rewrites, copies and memory growing with the data; (2) Cave splitting rows into months by a date column, which needs a date in every Dataset and splits uploads that span months; (3) keeping 3, or 1, earlier copies, which multiplies storage at this size when the Workbooks already hold the way back; (4) `data.json` returning only recent Parts, which breaks pages that expect every row; (5) refusing an add whose rows mostly match a Part, which refuses any report that repeats most rows each period; (6) `Part date` only when the rows have no date of their own, which leaves pages unsure whether the column exists.
