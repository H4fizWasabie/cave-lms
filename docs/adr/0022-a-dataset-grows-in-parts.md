# A Dataset grows in Parts, with no earlier copies

Amends ADR 0017 and ADR 0021. Learners upload the same Excel report every week or month for years: one class's attendance is about 8,700 rows a month, so a few years is 300,000 rows or more. A Dataset was one table capped at 50,000 rows, and each "add" rewrote the whole table and kept 3 earlier copies, so it hit the cap within months, held up to four copies in storage, and loaded everything into memory for every change. A Dataset is now made of Parts, one per confirmed upload. Adding data stores only the new Part, a Part can be replaced or deleted on its own, and a replaced Part keeps its place, so a page that takes the last row for a key still treats the newest upload as newest. `data.json` still returns every row, Part after Part, so pages written for ADR 0017 keep working.

A growing Dataset only works if every upload is read the same way, so the first Part sets the recipe (its sheet, matched by name ignoring case, and its header row), and each new Part is read with it: Cave never combines other sheets into an added Part, and asks the Learner to pick a sheet when none has that name. Every Part has the Dataset's columns. An add whose rows mostly repeat one existing Part is refused, with an offer to replace that Part. The recipe lasts while one Part remains.

Limits: each upload keeps the 50,000-row and 10 MB limits, which bound Clean-up's memory. A Dataset behind the Learner's own page has no row cap; only the Storage allowance limits it, and a bigger allowance is a Plan with more storage. A Dataset Cave builds a Dashboard from (ADR 0019) keeps a 50,000-row total, because the builder reads it whole. A Part counts against the allowance alongside its Workbook, as ADR 0021 decided, so 1 GB holds roughly 100 to 150 months of attendance data like the client's.

Cave keeps no earlier Datasets and has no Restore. Each Workbook stays in the Folder, so a Part removed by mistake, or by replacing the data, comes back by adding it again from its Workbook. Picking a Workbook on a Dashboard (issue #401) becomes adding or replacing a Part from it. Existing Datasets become one Part each, keeping their Workbook link; their earlier copies stay until that Dashboard's data next changes.

Rejected: (1) raising the 50,000-row cap, which keeps whole-table rewrites, copies and memory growing with the data; (2) Cave splitting rows into months by a date column, which needs a date in every Dataset and splits uploads that span months; (3) keeping 3, or 1, earlier copies, which multiplies storage at this size when the Workbooks already hold the way back; (4) `data.json` returning only recent Parts, which breaks pages that expect every row.
