# Deployments move to the pages subdomain

Deployments live at `pages.cavelms.com/<username>/<name>/`, not `cavelms.com/d/<username>/<name>/`. A Learner's page is unreviewed HTML and can pose as a login screen. Safe Browsing flags by host, so one flagged Deployment on `cavelms.com` put a red warning on the login page for every Learner until Google cleared it, days later. On its own host, a flagged Deployment takes down `pages.cavelms.com` and the LMS keeps working. The client still declined a separate domain (ADR 0007), so this stays under `cavelms.com`, needs no domain bought, and Caddy issues the certificate. It is a partial wall: repeated abuse can still get the whole of `cavelms.com` flagged, and spam filters judge the parent domain. A separate domain stays the only full wall.

The one app answers both hosts and routes by host. The Deployments host serves only `/<username>/<name>/...` (the page, `data.json`, `charts.js`, `data/<key>`, and the Username redirect of ADR 0023); everything else there is not found, and it renders none of the site's chrome or links, so it is never a second copy of the LMS. The main host serves no Deployment. Its `/d/...` answers a permanent redirect to the same path on the Deployments host, keeping the file and query, with `Access-Control-Allow-Origin: *` so a sandboxed page still open at an old link can follow it for its data. These redirects stay for good, as ADR 0002 does for old domains: Learners have shared the old links. The session and language cookies carry no `Domain`, so a browser never sends them to the Deployments host. The page and data CSPs name the Deployments origin in `connect-src`, since data is served only from there.

The host comes from `PAGES_BASE_URL`, `https://pages.` in front of `PUBLIC_BASE_URL`'s host when unset (staging: `pages.staging.cavelms.com`). Moving Deployments to a separate domain later is that setting, a Caddy block and DNS. Production and staging each need an A record for `pages` before they are deployed, or Caddy cannot get the certificate. Rejected: (1) a separate domain, declined by the client; (2) a host per Learner, which needs a wildcard certificate and can set cookies for the parent domain (ADR 0007); (3) keeping `/d/` on the main host and only adding the subdomain, which leaves the flag on `cavelms.com`.
