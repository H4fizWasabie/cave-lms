# Old domains redirect to the current one forever

When Cave LMS moves to a new domain, the old domain keeps a permanent (308) redirect to the new one, keeping the path, for as long as the service runs. The old domain is kept renewed and its redirect block is never removed. The Certificate PDF prints its verification link from `PUBLIC_BASE_URL` when it is downloaded, so a printed or saved copy carries whatever domain was current then and can never be updated. Dropping an old domain would break every copy made under it. Verification paths (`/certificates/<id>`) don't change with the domain, so no app change is needed: the redirect alone keeps them working. Rejected: (1) letting old domains lapse after a grace period, which breaks printed Certificates with no way to fix them; (2) a fixed verification domain separate from the site, which adds a second domain to run from day one when a redirect does the same job. The procedure is in `docs/runbook.md`, Changing the domain.
