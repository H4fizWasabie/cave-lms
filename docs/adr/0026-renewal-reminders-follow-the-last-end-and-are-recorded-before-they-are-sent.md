# Renewal reminders follow the last end and are recorded before they are sent

A Plan period, a year of CaveText Pro and Ebook access just end on their day (first buyers, 2026-10-29, reach theirs on 2027-10-29), and 90 days after the last Plan period a Learner's Workbooks and Datasets are deleted. Renewing early loses no days, since the new year starts when the current one ends, so a timely email costs the Learner nothing. The daily prune now sends Renewal reminders: 30 days before, 7 days before and when an item has ended, plus one warning 7 days before the deletion of Lab data when the Learner has Workbooks or Datasets to lose.

Each reminder follows the end of the item's last stacked period, honouring an Admin ending it early, because that is when access actually stops. A Learner who has renewed has a later end and is skipped without any renewal check; the next year has a different end and gets its own reminders. Only the Lab Plan and CaveText Pro are reminded (Ebook access is named inside the CaveText Pro year it comes with); Plans that exist only to be assigned by hand are skipped, while a hand-given Pro Plan counts like a bought one. A run sends only the latest stage reached, so a Learner whose end is 5 days away gets the 7-day reminder and not the 30-day one, and an end more than 7 days in the past gets nothing, so the first deploy does not write to Learners long lapsed. A Learner gets one email per stage listing every item reaching it, so a COMBO buyer gets one, not two.

A reminder is recorded in `renewal_reminders` (Learner, item, end, stage) before it is sent. A restart between the two loses that one email and never sends it twice; a failed send is logged and not retried, as for the other service emails. Service emails have no opt-out, and there is no on-site banner or Admin view.

Rejected: (1) sending first and recording after, which doubles an email whenever the server restarts in between; (2) reminding per Plan period, which would email a Learner who already renewed; (3) one email per item, which sends a COMBO buyer two near-identical emails; (4) catching up every missed stage, which sends a Learner three emails in one day after the server was down.
